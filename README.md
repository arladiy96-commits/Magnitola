# GAZ Спидометр — AutoLink (v0.5)

Текущая экспериментальная Android-сборка для POCO / магнитолы Газели. **Главный экран теперь спидометр**, а не навигационная карта и не отладчик USB.

- Большой цифровой спидометр и многослойная приборка 16:9 в сине-золотом стиле.
- Дуга зависит от реальной GPS-скорости; без свежих координат показывается «—», а не вымышленное значение.
- Курс, высота, GPS-точность, пробег и время вычисляются по данным телефона; интернет для спутниковой скорости не нужен.
- GPS работает в foreground service c постоянным Android-уведомлением и не зависит от видимости окна приложения.
- Экспериментальный H.264-канал кодирует ту же приборку для AutoLink; параметры 1280×720/30fps/3.5Mbit.
- Экран блокируется в горизонтальной ориентации; одно касание открывает кнопки подключения и диагностики.

**Важное ограничение:** сборка и фоновый GPS проверены на уровне кода/CI, но реальная передача на магнитолу по проприетарному AutoLink не подтверждена тестом на оборудовании. Если Android уничтожит Activity, USB-сессия всё ещё может прерваться: её перенос в отдельный сервис — следующий этап. Для POCO полезно выставить приложению «Без ограничений» в настройках расхода батареи.

APK в разделе [GitHub Actions](../../actions/workflows/build.yml), последний успешный запуск, архив с app-debug.apk.

## История USB-протокола и диагностического режима


Экспериментальный Android-проект для исследования подключения смартфона **POCO (Android 16)** к автомобильной магнитоле с поддержкой AutoLink.

## Что уже реализовано

- Обнаружение **Android Open Accessory (AOA)** с производителем Sunplus, Inc. и моделью DVD.
- Проверка и запрос USB-разрешения.
- Открытие аксессуара и чтение **только входящих** данных (до 64 КиБ за сессию).
- HEX-лог полученных байтов, журнал событий USB и экспорт TXT.
- Автоматическая сборка debug APK в GitHub Actions.

**Безопасность:** приложение не отправляет команды магнитоле, не перепрошивает её, не подключается к интернету и не требует root. Это первый тест соединения, а не замена AutoLink.

## Скачать APK

1. Открой [GitHub Actions — Build USB Probe APK](../../actions/workflows/build.yml).
2. Выбери последний **успешный** запуск.
3. Внизу страницы, в разделе **Artifacts**, скачай AutoLinkUsbProbe-debug-apk.
4. Распакуй ZIP и установи app-debug.apk на POCO.

Либо запусти сборку вручную: **Actions → Build USB Probe APK → Run workflow**.

## Проверить с магнитолой — обновлённая диагностика после теста 10:38

1. Установи самый свежий APK из [Actions](../../actions/workflows/build.yml).
2. На магнитоле открой режим AutoLink. Временно исключи автоматический запуск оригинального AutoLink на POCO, чтобы он не перехватил USB.
3. Запусти **AutoLink USB Probe** на телефоне до подключения кабеля. В приложении нажми кнопку **«Автотест: пройти 2 известных шага»** (это явное разрешение отправить два строго заданных ответа, если магнитола их запросит).
4. **Полностью отсоедини USB-кабель от телефона на 5 секунд и подключи обратно.** Чтение запустится само по AOA ATTACHED — шаги 1/2 нажимать не нужно.
5. Если в логе увидишь `RX 10 байт`, далее автотест отправит VERSION_RESPONSE; после второго ожидаемого кадра — AUTH_RESPONSE. Все неожиданные сообщения сохраняются в логе, но на них приложение не отвечает.
6. Если появится `USB открыт 7 секунд, но RX = 0 байт`, не нажимай кнопки 3/4. Это значит **пока не поступило ни одного байта**, а не ошибку парсера. Проверь кабель/порт, что магнитола находится в AutoLink, и повтори физическое подключение.
7. Сохрани лог в файл и пришли его для анализа.

**Важно:** приложение само открывает AOA-порт, но не пытается перепрошить магнитолу или послать случайные команды. Автотест остаётся строго ограниченным двумя уже исследованными ответами. Новые этапы протокола ещё не реализованы.


## Пятый этап — обнаружение сервисов (после теста 10:56)

Последний подтверждённый пользователем USB-обмен:
- RX 00 03 00 06 00 01 00 01 00 0A (VersionRequest 1.10)
- TX 00 03 00 08 00 02 00 01 00 0B 00 00 (VersionResponse 1.11)
- RX 00 03 00 04 00 03 00 00 (EncapsulatedSsl ID3)
- TX 00 03 00 04 00 04 08 00 (AuthResponse status0)
- RX 00 03 00 04 00 04 08 00 (AuthComplete ID4)

Дизассемблирование ARM64-библиотеки AutoLink 2.0.59 подтверждает, что после ID4 родной Controller вызывает sendServiceDiscoveryRequest. Запрос состоит из protobuf-полей manufacturer, model, version, device name, width, height. Приложение формирует этот запрос из стандартных сведений Android без серийных номеров.

**Новый тест:** отключи USB, открой приложение, нажми «Автотест: пройти 2 известных шага», заново подключи USB. После строки **AUTH_COMPLETE** нажми **«5. Запросить сервисы магнитолы (SERVICE_DISCOVERY)»** и пришли весь лог, особенно ответ ID6. Пятая команда требует явного нажатия и не выполняется автоматически. Это экспериментальная сборка, вывод видео пока не реализован.

## Технический стек

- Java, Android SDK 35 (minSdk 26), Android Open Accessory.

- GitHub Actions собирает assembleDebug.

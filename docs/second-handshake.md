# Тест №2 — подтверждённый ответ на VERSION_RESPONSE и следующий этап

## Наблюдение на POCO 22 октября 2026, 10:18

Подключение: Android 16, SDK 36, USB AOA Sunplus, Inc. / DVD, версия 2.0.

Входящий пакет:
```hex
00 03 00 06 00 01 00 01 00 0A
```
Ответ разработанного приложения:
```hex
00 03 00 08 00 02 00 01 00 0B 00 00
```
**И после ответа магнитола действительно выдала новый пакет:**
```hex
00 03 00 04 00 03 00 00
```

Контрольный канал 0, флаги 0x03, payload length 4, message ID 3, данные 00 00.

## Почему это не надо интерпретировать как полноценный TLS ClientHello

В нативной библиотеке AutoLink 2.0.59: `Controller::routeMessage` по адресу 0x4f064 содержит jump table по адресу 0x28652. Вариант №3 перенаправляет выполнение на 0x4f2c4; там печатается журнал `[CONTROL] <- EncapsulatedSsl`, далее вызывается `Controller::sendAuthResponse(0)` по адресу 0x4fea0. В этом обработчике:
- создаётся `autolink::AuthResponse`;
- записывается `status=0` в protobuf-поле №1;
- `MessageRouter::marshallProto(4,...)` создаёт сообщение ID 4;
- `MessageRouter::queueOutgoingUnencrypted` отправляет его как обычный кадр.

Проверка `AuthResponse::SerializeWithCachedSizes` по адресу 0x5c748 показывает `WireFormatLite::WriteInt32(field_number=1, value=status)`, следовательно `status=0` кодируется `08 00`.

Точный предполагаемый ответ следующего теста:
```hex
00 03 00 04 00 04 08 00
```

**Ограничение:** входящие 8 байт и переход после ответа версии подтверждены реальным логом, а байты исходящего AUTH_RESPONSE восстановлены статически и пока не проверены на машине.

## Приложение v0.3

- Читает и собирает входящие кадры даже если USB разделит их на несколько read() или склеит несколько кадров в один.
- Добавлена кнопка `4. Ответить AUTH_RESPONSE (status=0)`.
- Отправка этого ответа возможна только после получения точных 10 байт версии 1.10, успешного вызова версии 1.11, и точных 8 байт `00 03 00 04 00 03 00 00`.
- Отправка каждого ответа происходит не более 1 раза за сессию.
- После ответа остаётся только читать и логировать; автоматических дополнительных сообщений нет.

## Следующий ожидаемый этап (по родной библиотеке)

В случае получения сообщения №4 нативный `Controller::routeMessage` попадает в ветку `[CONTROL] <- AuthComplete`, после чего вызывает `Controller::sendServiceDiscoveryRequest` с ID 5. Тест v0.3 документирует полученный кадр №4, но не пытается отправлять сложный ServiceDiscoveryRequest без согласованных параметров.

Это **проприетарное поведение данного APK** — не стоит автоматически копировать универсальную реализацию TLS из открытого Android Auto для этого устройства.

Дальнейшие действия: на стоящем автомобиле открыть тестовое приложение; «2. Слушать USB» → дождаться версии → «3. Ответить VERSION_RESPONSE» → дождаться ENCAPSULATED_SSL → «4. Ответить AUTH_RESPONSE» → через 5–10 секунд экспортировать лог.
